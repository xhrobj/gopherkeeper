# 🚀 Быстрый запуск GophKeeper

Это **гайд по быстрому локальному запуску**. Более подробная версия этого документа с описанием всех параметров находится в [🤓 полном руководстве по настройке и запуску](SETUP.md).

## Требования

Для локального запуска нужны:

* Go 1.26
* Docker с Docker Compose
* `make`
* OpenSSL

> ⚠️ На Windows выполняйте команды этого руководства в **Git Bash**. Запуск целей Makefile из PowerShell и `cmd.exe` не поддерживается.

## 0. Проверить окружение

```bash
go version
docker --version
docker compose version
make --version
openssl version
docker info >/dev/null && echo "Docker daemon: OK"
```

Если какая-либо проверка завершается ошибкой, установите или запустите соответствующий инструмент перед продолжением.

## 1. Клонировать проект

```bash
git clone https://github.com/xhrobj/gopherkeeper.git
```

Перейдите в каталог проекта:

```bash
cd gopherkeeper
```

Все последующие команды выполняются из корня проекта.

## 2. Запустить Сервер

### 2.1. Создать локальный `.env`

Скопируйте пример конфигурации:

```bash
cp .env.example .env
```

### 2.2. Сгенерировать серверные секреты

```bash
make gen-jwt-secret
make gen-record-master-key
```

Скопируйте первое полученное значение в `JWT_SECRET`, а второе — в `RECORD_MASTER_KEY` файла `.env`:

```dotenv
JWT_SECRET=<generated-jwt-secret>
RECORD_MASTER_KEY=<generated-record-master-key>
```

В исходном `.env.example` эти поля намеренно оставлены пустыми.

Это минимальная конфигурация, необходимая для локального запуска Сервера. Остальную подготовку выполнит `make run-server`.

### 2.3. Запустить Сервер

Убедитесь, что Docker запущен, и выполните:

```bash
make run-server
```

Команда:

* запустит PostgreSQL
* создаст локальные TLS-сертификаты
* соберёт Сервер
* применит миграции
* запустит Сервер GophKeeper

Оставьте этот терминал открытым.

Сервер запущен 👍

## 3. Запустить Клиент

Откройте второй терминал и перейдите в корень проекта.

### 3.1. Создать конфиг Клиента

Скопируйте пример конфигурации:

```bash
cp configs/client.example.json configs/client.json
```

В созданном `configs/client.json` укажите путь к локальному CA-сертификату (поле `ca_cert_file`):

```json
{
  "transport": "https",
  "address": "localhost:8080",
  "grpc_address": "localhost:50051",
  "ca_cert_file": ".local/certs/ca.pem",
  "session_dir": "",
  "cache_dir": ""
}
```

Сертификат по этому пути был создан командой `make run-server`.

Поля `session_dir` и `cache_dir` можно оставить пустыми. В этом случае Клиент будет использовать системные пользовательские каталоги. Подробнее о конфигурации Клиента можно прочитать в [🤓 полном руководстве по настройке и запуску](SETUP.md).

### 3.2. Собрать Клиент

```bash
make build-client
```

### 3.3. Настроить текущую shell-сессию

Добавьте каталог с собранным Клиентом в `PATH` и укажите путь к созданному конфигу:

```bash
export PATH="$PWD/bin:$PATH"
export CONFIG=configs/client.json
```

Теперь в текущем терминале Клиент можно запускать короткой командой `gkeep`.

Клиент настроен и готов к запуску 👍

## 4. Проверить подключение

Выполните:

```bash
gkeep health
```

Ожидаемый результат:

```text
Server status: ok
```

## 5. Начать работу

Для работы через отдельные CLI-команды откройте [💻 руководство по консольному интерфейсу](CLI.md).

Для запуска терминального интерфейса выполните:

```bash
gkeep tui
```

Основной сценарий работы с TUI описан в [🔐 README проекта](../README.md).
